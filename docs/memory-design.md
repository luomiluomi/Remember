# 角色记忆

记忆作用域是角色 ID。一个角色拥有多个维度，每个维度拥有多张事实卡。会话永久绑定角色 ID，新旧会话都从该角色的已启用记忆中检索。

| 维度 | 内容 |
| --- | --- |
| 偏好 | 喜好、不喜欢的事 |
| 日常 | 作息、习惯 |
| 人际 | 用户描述的重要关系 |
| 经历 | 过往事件 |
| 目标 | 长期愿望、计划 |
| 沟通方式 | 称呼、回答方式 |

## 写入

用户发送消息且回答成功结束后，为启用自动记忆的角色发起一次独立的 DeepSeek 提取请求。每次最多两张卡，每张表达一个稳定事实，保存分类、原文、创建时间、会话和消息 ID。原文必须出现在用户消息中，单条不超过 160 字。跳过闲聊、临时请求、推测和敏感内容。模型过滤不能保证完全正确，用户可以直接更改、停用或删除。

同角色的任务串行执行，去除重复文本。提取期间若用户维护了该角色的记忆，放弃这次结果，避免覆盖维护操作。新卡自动启用，旧卡的启用状态保持原值。新建角色默认开启自动记忆，现有角色保持用户已保存的选择。

## 读取

有已启用卡片时，回复前先用独立模型请求判断问题关联的维度，分类模型只接收问题及可用维度名。最多选三个维度。再按文本相关性排序，仅加载所选维度的卡片，每维度最多两张，总计最多六张。分类失败时仅使用沟通方式维度。

提取与维度选择都会额外调用 DeepSeek，产生延迟和 API 费用。当前相关性排序使用字符重合，尚未引入语义向量和矛盾事实合并。记忆以背景资料形式进入系统提示，不作为指令执行。

## 管理

记忆页以角色 Tab 隔离，维度分组下显示卡片。支持手动新增、编辑、启停、删除和查看来源原文。存储在当前设备的站点本地存储，DeepSeek 历史 ZIP 不包含角色和记忆。当前尚未提供角色与记忆的独立备份。

## 导入对话的手动提炼

仅导入的会话支持，通过会话列表的「⋯ → 提炼到角色」选择已有角色。读取当前分支中的用户文本，分段提取；附件及 AI 回答不作为用户事实来源。提炼记录包含目标角色、进度和完成时间。目标在开始后锁定，成功完成后不再允许重复提炼，同一设备重新导入同 ID 也保留标记。中断或失败可从记录进度继续。记录保存在本地，清除数据或换设备后不能保证一次性约束；不支持跨标签页事务锁定。

默认 DeepSeek 不允许编辑人设、名称、性别或头像，不附加 Remember 的角色提示。允许单独开启自动记忆；有相关启用卡片时，只加入检索到的背景资料。其他角色继续使用用户自定义人设。
