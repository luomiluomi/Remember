# 角色记忆与上下文摘要

记忆作用域是角色 ID。每个角色可有多张记忆卡，会话绑定角色后，仅检索该角色的已启用卡。

| 维度 | 内容 |
| --- | --- |
| 偏好 | 喜好与厌恶 |
| 日常 | 作息与习惯 |
| 人际 | 用户描述的重要关系 |
| 经历 | 用户的过往事件 |
| 目标 | 长期愿望与计划 |
| 沟通方式 | 称呼、回答语气与方式偏好 |
| 特性 | 用户明确自述的个人特点 |
| 情绪支持 | 用户明确表达的安慰方式与支持需求 |

## 写入与合并

开启自动记忆的角色，在成功完成回答后，额外调用 DeepSeek 整理当前用户文本。每次最多六项，记忆正文最长800字，以“用户”为主体；独立原文证据必须存在于输入。已有卡片不会批量自动改写，读取时明确旧卡中的“我”指用户。

提取器可指定同角色、同维度的已启用卡合并，累积来源原文；会话及消息ID指向最近一次合并输入。模型不能保证摘要、分类和合并完全正确，也没有完整的矛盾事实处理系统。只有逐字证据校验，不等于人工核实。用户可在独立详情页维护内容、维度、启用状态和来源。

同角色的日常提取任务串行执行；提取期间若角色记忆发生变化，放弃本次结果，避免覆盖维护操作。新卡自动启用，新建自定义角色默认开启自动记忆，已有角色保留原设置。

## 按维度读取

存在已启用卡时，回复前通过独立模型请求判断问题关联的维度。分类模型只接收问题与可用维度名称，最多选择三个维度。随后按文本相关性排序，每维度最多两张、总计最多六张。分类失败时仅使用沟通方式维度。当前本地排序使用字符重合，并非语义向量检索。

角色人设描述助手，记忆描述用户，对话摘要描述双方此前交流；三者明确区分。自定义角色结合近期对话适配表达方式，不从单次措辞推断稳定人格。默认 DeepSeek 固定官方身份，不附加自定义角色人设，但可启用自动记忆。

## 导入对话的手动提炼

仅导入会话支持，通过列表「⋯ → 提炼到角色」选择已有角色。读取当前分支的用户文本并分段提取；附件及 AI 回答不作为用户事实来源。开始后锁定目标角色，保存处理进度；中断或失败可继续。没有新增或更新时不标记成功，允许重试。

成功后以会话ID记录一次性完成状态，同设备重新导入相同ID仍保留标记。此约束仅保存在本地，清除数据或换设备后不再保留；没有跨标签页事务锁。

## 长对话摘要

请求历史超过24000个JSON字符且超过10条消息时，整理较早消息，保留最近8条。阈值是字符估算，不是模型token计数。分段摘要保存在独立的 `remember-context-summaries-v1` 本地存储，不混入角色长期记忆，也不主动展示为卡片。

按会话保存分支前缀的SHA-256指纹，分支变化后重新生成。整理开始、结束显示提示，失败保留原上下文；包含工具调用的历史暂不裁剪，以保护调用与结果配对。当前重新生成摘要会重读该分支的较早消息，不是增量token压缩器。

## 数据与费用

角色、记忆、提炼标记、摘要保存在当前设备的站点本地存储，未加密。DeepSeek历史ZIP不包含这些数据，目前没有独立备份。清除应用数据会丢失它们。

自动提取、维度选择和上下文摘要都会额外调用 DeepSeek、增加延迟并使用API额度。模型输出仍需用户维护；真实模型的内容质量与端到端提取效果不由静态检查或模拟测试保证。
